# 저널리즘 안전장치

참고한 흐름: 국내 언론계 생성형 AI 준칙들(인터넷신문윤리위원회 가이드라인, 언론단체 공동 준칙, 언론사별 AI 활용 준칙)과 AP 생성형 AI 지침의 공통 원칙.
공통점은 다섯 가지다. AI 결과는 검증 전 자료다. 허위 인용 금지. 사람 검수 없이 송고 금지. AI 사용 표시. 민감 정보 입력 주의.

## 1. 사실
- AI 출력은 모두 '검증 전'이다. 편집자가 확인해야 '확인됨'.
- 원문에 없는 인용·발언·숫자·날짜·직함을 만들지 않는다.
- 인용문은 원문 문자열과 정확히 일치해야 한다. 일치 검사를 코드로 한다.
- 숫자는 원문 숫자와 대조한다. 단위 변환(억·만)은 허용하되 값이 같아야 한다.
- 근거 없는 문장은 노란색으로 표시하고 승인 버튼 옆에 개수를 띄운다.
- "~로 알려졌다", "업계에 따르면" 같은 출처 흐리기 표현을 AI가 만들지 않게 프롬프트로 막는다.

## 2. 사람의 결정
- 승인·발행은 편집자 버튼으로만.
- 자동 송고, 자동 게시 기능을 만들지 않는다(4단계 검토 전까지).
- 엠바고 해제 전에는 승인 버튼을 잠근다.

## 3. 표시
- 기사 끝: `config/publication.yaml`의 `ai_disclosure.article` 문구.
- 카드뉴스 마지막 장: `ai_disclosure.cardnews` 문구.
- front matter에 `ai_assisted: true`, `human_reviewed: true/false`.

## 4. 민감 분야
- sensitive_class(disaster / accident / crime / election)는 'AI 초안 제한'.
  - 초안을 만들지 않고 사실 정리와 취재 질문만 만든다.
  - 편집자가 직접 '초안 생성'을 눌러야 만든다. 이때 경고 문구를 띄운다.
- 피해자·미성년자 실명, 주소는 기사 초안에 넣지 않는다.

## 5. 개인정보
- 제보 메일은 AI로 보내기 전 가린다(기본 켜짐).
  - 대상: 이름(제보자 서명), 전화번호, 이메일, 주소, 주민·계좌 번호 형태.
  - 방식: `[제보자]`, `[전화]`, `[주소]` 같은 자리표시자. 원본은 DB에만.
- 보도자료 담당자 연락처는 공적 연락처라 가리지 않아도 된다(설정으로 바꿀 수 있음).
- 로그에 본문 전문, 비밀번호, API 키를 남기지 않는다.

## 6. 사진
- 출처 불명 사진은 사용 보류.
- 보도자료 첨부 사진은 '제공: 기관명'을 캡션에 붙인다.
- AI로 사진을 만들거나 고치지 않는다(자르기·크기 조절 제외).

## 7. 저작권
- 다른 매체 기사를 그대로 옮기지 않는다. 메일에 다른 기사가 붙어 오면 참고 자료로만 표시.
